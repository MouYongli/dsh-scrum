# 架构决策记录

本目录保存 Architecture Decision Record（ADR）：一次已经生效、且改起来有代价的技术决策。

## 什么时候写 ADR

需要写：工具链选型、运行时依赖选型、持久化格式、公共 Contract 的版本策略、跨包的结构约束。

不需要写：一次性实现细节、可以随时替换的局部写法、已经由 `AGENT.md` 或 `docs/` 中现有规范覆盖的内容。

## 格式

文件名为 `NNNN-kebab-case-title.md`，编号连续递增，不复用。正文使用中文，包含以下小节：

| 小节 | 内容 |
|---|---|
| 状态 | `已接受` / `已废弃` / `被 NNNN 取代` |
| 背景 | 触发这次决策的问题和约束 |
| 决策 | 实际选了什么，包含版本号等可验证的事实 |
| 理由 | 为什么是它，以及被排除的选项因何被排除 |
| 后果 | 接受了哪些代价，什么条件下需要重新评估 |

已被取代的 ADR 不删除，只把状态改为 `被 NNNN 取代`，并在新 ADR 的背景中说明差异。
