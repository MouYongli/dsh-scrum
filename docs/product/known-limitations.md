# 已知限制

本文列出 Community MVP 已知的边界。每条都说明现状、影响，以及为什么没有在这一版解决。追踪用的 Issue 编号写在条目末尾。

## 1. 浏览器半边还没接上宿主

**现状**：Sidebar 入口、工作台、Backlog、看板和会话权限控件都已实现并有测试，但浏览器与 Harness Host 之间的调用通道还没接通。装上插件后界面能打开，数据读不到。

**为什么**：Host 侧读不到「当前打开的是哪个 Workspace、哪个 Session」。已安装的 Harness 包里，`ctx.sessions` 是全部 Session 的仓库、没有「当前」的概念，宿主端 Workspace 实体包也不在依赖树里 —— 知道答案的是浏览器和发起调用的那个 Agent Session。要么由调用方传进来再由 Host 对着 Workspace 注册表校验，要么依赖宿主端 Workspace 包；两条路都需要对着跑起来的 Harness 验证。

**影响**：本版的界面部分不可用。领域、存储、用例、Host API 和 Agent Tools 都可用，并有端到端测试覆盖。

**绕过**：暂无。

## 2. 删掉最新的工作项后，编号会被重新发放

**现状**：工作项编号取「现有工作项里的最大编号加一」。删掉 `SCR-7` 之后，下一个新建的仍然是 `SCR-7`。中间的空缺（删掉 `SCR-1`）不会被填。

**为什么**：不重发需要一个持久化的高水位标记，而那是持久化格式决定，不是实现细节。计数器还是「第二个答案」，它和文件不一致的那一次恰好是最需要它的那一次。

**影响**：工作项编号会出现在 Activity 记录、commit message 和对话里。如果你删掉了最新的工作项又新建一个，那些引用会指向另一件事。

**绕过**：不要删除工作项，改用状态或标签表达「不做了」。删除本身是高风险操作，Agent 执行前会先问。

Refs #54

## 3. 没有实时同步，也没有多人协作

**现状**：Community 是单个本地用户。没有成员管理、没有评论和提及、没有实时事件。

**为什么**：这些是 Teams 能力，由远程服务提供。插件不在客户端组合商业版本。

**影响**：两个人各自打开同一个仓库会得到两份互不相干的数据，除非通过 Git 同步 `.scrum/`。通过 Git 同步是可行的，但冲突需要按普通文本冲突处理。

Refs 见[版本设计](editions.md)

## 4. 归档项目只能整体只读

**现状**：项目归档后一切写入都被拒绝，会话的「可写」自动降级为只读。

**为什么**：归档是一份记录。

**影响**：想继续编辑必须先恢复项目。界面会说明降级的原因。

## 5. 重复点击当前会话不会退出 Scrum

**现状**：Scrum 是与对话并列的模式，点任意会话都会回到对话。但如果点的正是**当前已经选中**的那个会话，或者「新建会话」复用了你此刻所在的空会话，Scrum 不会退出。

**为什么**：宿主没有发布「用户选中了某个会话」的事件，插件能观察的只有会话列表快照里的「当前会话」。上面两种操作不改变这个值，浏览器侧看不见任何变化。

**影响**：很小——这两种情况下你本来就停在那个会话上。

**绕过**：按 Esc，或点工作台头部的「返回对话」。

## 6. 尚未实现的部分

以下在 Community 的规划内，但不在本版：

- 备份、恢复与一致性检查
- Schema 迁移
- 导入导出
- 燃尽图与速率
- 每日站会、评审与回顾视图
- 评论与附件
- 性能与规模基线
