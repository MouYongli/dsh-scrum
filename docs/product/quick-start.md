# 快速开始

本文面向第一次使用 DeepSeek Harness Scrum 插件的用户，说明如何把一个代码项目纳入 Scrum 管理，跑完第一个 Sprint，并让 Agent 参与进来。

安装前请先读[已知限制](known-limitations.md)：本版本是 Community MVP，有几处需要你知道的边界。

## 1. 装上插件

在插件仓库根目录把 Bundle 挂进你的 Harness Profile：

```bash
pnpm dev:link      # 挂载
pnpm dev:config    # 确认组合结果里有且只有 Bundle 一行
```

`pnpm dev:config` 应当输出：

```text
# == @dsh-scrum/scrum-harness-bundle
- id: scrum
  name: '@dsh-scrum/scrum-harness-bundle'
```

只有 Bundle 这一行是对的。出现 `scrum-harness-host` 或 `scrum-harness-client` 说明 patch 写了工作区内部包名，Shell 会启动失败。

完整命令、换 Profile 和摘除方式见[本地开发循环](../development/local-development.md)。

## 2. 打开你的项目

挂载是全局的，启动目录才决定这次管理哪个项目：

```bash
cd ~/你的代码项目
npx @deepseek-ai/dsh web
```

Scrum 数据会写在这个目录的 `.scrum/` 里。换一个项目不需要重新挂载，`cd` 过去再启动即可。

## 3. 建立 Scrum 项目

侧栏底部会出现 Scrum 入口，点开工作台。首次打开时它会告诉你这个工作区还没有 Scrum 项目，并给出创建表单：

- **项目名称**：给人看的名字，可以是中文。
- **项目标识**：工作项编号的前缀，例如填 `SCR` 就会得到 `SCR-1`、`SCR-2`。它**不能修改**，也不会从项目名称推导 —— 中文项目名下任何推导都是猜。
- **项目描述**：可留空。

创建后 `.scrum/` 目录出现，里面就是这个项目的权威数据。它是普通的 JSON 与 JSONL 文件，可以提交进你的仓库，也可以直接用编辑器读。

## 4. 排 Backlog

工作台的第一个页签是产品 Backlog，也就是还没有进入任何 Sprint 的工作项。

- **新建工作项**：选类型（史诗／故事／任务／缺陷）、写标题，其余可以之后再补。
- **排序**：每一行有「上移一位」「下移一位」。这是键盘可达的，因为排 Backlog 是 Product Owner 的主要动作。
- **详情**：点标题打开详情，可以改标题、描述、优先级、估算和标签，勾选验收标准，设置上级工作项与依赖，或者标记阻塞。
- **估算留空表示「还没估」**，与估算为 0 不是一回事，Sprint 进度会把两者分开计数。
- **分组与筛选**：可以按类型、优先级或上级分组，也可以按文本、是否阻塞筛选。

## 5. 跑一个 Sprint

切到「Sprint 看板」页签：

1. **新建 Sprint**：填名称、目标和起止日期。日期是「这个 Sprint 说好什么时候结束」的基准，之后不能改 —— 要改就是重新立项。
2. **规划**：下方两栏，左边是本 Sprint 的工作项，右边是产品 Backlog，逐条「加入本 Sprint」或「移出 Sprint」。
3. **启动**：点「启动 Sprint」，确认一次。启动后工作项从「待规划」变成「待开始」。
4. **推进**：看板每张卡片上有「移动到」下拉，可以移到任意一列，包括往回移。全部通过键盘可达，没有必须拖拽的操作。
5. **结束**：点「结束 Sprint」。如果还有没完成的工作项，插件会逐条问你它去哪里 —— 退回产品 Backlog，还是带进另一个 Sprint。**没有默认值**：这两个选择对下一次规划的意义完全不同。全部选完之后确认按钮才可用。

## 6. 让 Agent 参与

切到「会话权限」页签。这里决定**当前这段对话**里的 Agent 能读写多少 Scrum 数据：

| 模式 | Agent 能做什么 |
|---|---|
| 关闭 | 看不到任何 Scrum 工具。这是默认值。 |
| 只读 | 可以查看项目、Backlog 和 Sprint。 |
| 可写 | 可以创建和修改工作项与 Sprint。 |

几件值得知道的事：

- 改动**在 Agent 的下一次调用生效**，不需要重启会话。
- 每段对话各自选择，互不影响；刷新页面不会丢。
- 即使选了「可写」，**启动 Sprint、结束 Sprint、删除工作项和修改项目设置仍然会先问你**。
- 「关闭」是让 Agent 看不到工具，而不是看到之后被拒绝 —— 后者会让模型反复尝试。
- 如果项目已归档，或者你在这个项目里的角色不再包含写入权限，页面会明确告诉你「可写」为什么没有生效，而不是让控件看起来能用。

## 7. 两边同时改同一条

你和 Agent 可能同时改同一个工作项。插件不会让后写的那一方悄悄覆盖先写的：

- 后写的一方会收到「内容已被其他人修改」，并附一个「刷新后重试」。
- 界面**不会自动刷新**，因为那会丢掉你正在输入的内容。
- 插件**不会自动重试**：拿错误里报的版本号重发一次，就是把覆盖写出来。
